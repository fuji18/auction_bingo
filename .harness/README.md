# .harness/

セッションを横断する軽量な作業状態を置くディレクトリ。スペック駆動体系(`docs/` / `.steering/`)や Claude Code の組み込み機能で賄えるものは**ここに複製しない**。

## ファイル

| ファイル          | 用途                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| `decisions.jsonl` | 横断的な技術判断のログ。1行1 JSON、**追記のみ**(削除・書き換えしない) |
| `state.json`      | ハーネスのメタ状態(モデル・Agent Teams の有効化状況)                  |

## ここに置かないもの(委ねる先)

| やりたいこと                   | 委ねる先                                                  |
| ------------------------------ | --------------------------------------------------------- |
| 作業計画・タスクリスト・進捗   | `.steering/[日付]-[タスク名]/`(steering スキル)           |
| チケット管理                   | GitHub Issues(`ticket` ラベル)                            |
| ロールバック・スナップショット | 組み込み checkpointing / `/rewind`(自作しない)            |
| セッション横断の学び           | auto-memory(修正指示・確認済みアプローチを理由付きで保存) |
| 実装とドキュメントの乖離       | `/sync-docs`                                              |

## decisions.jsonl の書き方

横断的で、後から「なぜこう決めたか」を追える必要のある技術判断を追記する。バランス調整の数値記録は**コミットメッセージ**に残す(development-guidelines.md)ので、ここには書かない。

```json
{
  "ts": "2026-07-22T10:00:00Z",
  "topic": "予知の山札除去",
  "decision": "選択数字は山札から除去しない",
  "why": "1ターン最大2枚減り40枚が25ターン持たない可能性。再出現頻度はsimで計測",
  "refs": ["docs/functional-design.md#未解決の設計判断"]
}
```
