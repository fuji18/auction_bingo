# 要求内容

## 概要

対戦終了後の「決着画面(ResultPanel)」と「試合後リプレイ(ReplayView)」を実装し、勝敗の根拠の明示と CPU の手の内の全開示を行う。(Issue #11 / P0 / フェーズ3)

## 背景

勝敗の納得と「次は勝てる」の実感を作るため、決着の根拠(どの基準で決まったか)を明示し、CPU が各ターンいくら入札し何を買っていたかを試合後に全開示する必要がある。現状の App.svelte は決着時に暫定表示(「決着画面とリプレイは次のチケット(#11)で追加します」)しか出しておらず、これを本実装で置き換える。

## 実装対象の機能

### 1. 決着画面 `ui/components/ResultPanel.svelte`
- 勝者・`decidedBy`(どの基準で決まったか)・順位表(standings)を表示する
- 同時ビンゴ・引き分け(winners 複数)を正しく表示する
- 「リプレイを見る」「新しいゲーム」の導線を持つ

### 2. 試合後リプレイ `ui/replay/ReplayView.svelte`
- 全ターンの events を再生し、入札額・購入スキル・選択数字・精算を開示する
- 予知で山札を操作したターンは、覗いた 3 枚と選んだ 1 枚を含めて開示する
- 「決着画面に戻る」導線を持つ

### 3. グルーピングの純粋ロジック `ui/replay/replay.ts`
- `GameEvent[]`(全ログ)をターン単位に分割・整形する純粋関数。UI とラベルを分離しテスト可能にする

## 受け入れ条件

### 決着画面
- [ ] 決着画面に「どの基準で決まったか」(bingo/reachCount/markCount/coins/none)が日本語で表示される
- [ ] 同時ビンゴ・引き分けが正しく(複数勝者として)表示される
- [ ] 順位表に各プレイヤーの完成ライン数・リーチ本数・総マーク数・コイン残が表示される

### リプレイ
- [ ] リプレイで全ターンの入札額・購入スキル・選択された数字・精算結果が確認できる
- [ ] 予知で操作したターンが、覗いた 3 枚と選んだ 1 枚を含めて開示される
- [ ] リプレイが同一シードから決定的に再現され、ゲーム中の表示(解決ログ)と矛盾しない

### 品質ゲート
- [ ] `npm run build` / `npm run typecheck` / `npm run lint` / `npm test` / `npm run format:check` が通る

## 成功指標

- リプレイの内容が `state.log`(reduce が確定させた events 列)からのみ導かれ、UI 側でルール判断を持たない
- 375px 幅で 3 人分の情報が破綻せず表示される

## スコープ外

以下はこのフェーズでは実装しません:

- リプレイの URL 共有(P2・backlog)
- タイトル画面の追加(本チケットの受け入れ条件外。決着→リプレイの相互遷移のみ実装する)
- 決着済みゲームの localStorage 永続化(決着時に保存は破棄する既存仕様を維持)
