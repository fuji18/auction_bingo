# 要求内容

Issue #9: シミュレーション基盤とKPI計測(P0 / フェーズ2 / depends #8)

## 概要

`core/` を UI 非経由で直接叩く自動対戦 CLI(`src/sim/`)を実装し、PRD のプライマリー KPI 7 項目を集計・出力する。これにより「ルールが成立していること」を主観ではなく数値で確認できるようにする。

## 背景

UI を 1 行も書く前に、シード固定の大規模自動対戦でバランスを数値で固める必要がある(PRD「7. バランス検証基盤」「成功指標(KPI)」)。未確定パラメータ(予知の価格・落札者ボーナス要否等)はこの基盤の初回計測結果をもって判断する。

## 実装対象の機能

### 1. 対局ドライバ(`play.ts`)
- 指定 config・シード・スロット別 Agent で 1 ゲームを最後まで決定的に進める
- `core/reduce` と `view` の射影のみを使い、Agent は `PublicView`/`SecretView` しか受け取らない

### 2. KPI 集計(`metrics.ts`)
- 決着した `GameState` から 1 ゲーム分の生データを抽出する純粋関数
- 生データ配列から KPI 7 項目を計算する純粋関数(ピアソン相関を含む)

### 3. CLI エントリ(`run.ts`)
- `--games` `--seed` `--agents` を解析し、N 戦を回して KPI レポートを出力する
- `npm run sim` スクリプトを追加する

## 受け入れ条件

### 対局ドライバ・CLI
- [ ] シード固定で 1 万戦を 5 分以内に完走する
- [ ] `npm run sim -- --games 10000 --seed 1 --agents leo,sara,hoarder` が動作する
- [ ] `console` は `src/sim/` でのみ使用(ESLint 規則に反しない)

### KPI 集計
- [ ] KPI 7 項目すべてが出力される(ビンゴ発生率 / スキル使用率 / 落札回数と勝率の相関(ピアソン r) / 支配的戦略の勝率 / 平均決着ターン / 終盤(残り5ターン)のスキル選択比率 / パス率)
- [ ] 終盤のスキル選択比率がスキル別(shift/vision/greed/なし)に分けて出力される
- [ ] 貯め込み/全力/スキル不買の各戦略の勝率が計測できる(スロット別勝率)
- [ ] `metrics` の集計・ピアソン相関のユニットテストが通る

### 全体
- [ ] `npm test` / `npm run typecheck` / `npm run lint` / `npm run build` が通る
- [ ] 実際に 1 万戦を回し、KPI の初回結果を Issue #9 にコメントで残す

## 成功指標(目標値。割ってもCIは赤にせず開発者への警告として扱う)

- ビンゴ発生率 95%+ / スキル使用率 40-60% / 相関 r ≥ 0.3 / 単一戦略の勝率 < 50% / 平均 16-20 ターン / 終盤単一スキル ≤ 70% / パス率 1-15%

## スコープ外

- UI(#10)
- 目標割れ時のバランス定数変更(適用はユーザー承認後。まずは計測して報告)
- KPI 閾値を CI の合否条件にすること(警告に留める)
