# オークション・ビンゴ（AUCTION BINGO） - アイデアメモ

<!-- 元ネタ: docs/ideas/memo.txt（ゲームデザイン・仕様まとめ Ver 2.3） -->

## プロダクトビジョン

**一言で言うと**: 運任せのビンゴを「オークション」「戦術スキル」「非AI型オートマタ」「$T \pm 1$ マークシステム」で再構築した、確率を自ら飼い慣らす対戦型 Web ボードゲーム。

- **「確率を飼い慣らす」体験**: 数字が出るのを祈るのではなく、リソースを投入して「欲しい数字、あるいはそれに近い数字」を能動的に引き寄せる。
- **ジレンマの構築**: 限られた「コイン」を、数字の**オークション（落札）**に使うか**スキル（確率操作）**に使うかという二重のコスト構造。
- **完全公開情報の安心感**: CPU に不気味な AI を積まず、行動ループを完全公開（非AI化）することで「敵の行動を計算し、ハメ殺すパズル」にする。

---

## 解決したい課題

1. 従来のビンゴは完全な運ゲーで、プレイヤーの意思決定が結果にほとんど影響しない（受動的な体験）。
2. 対戦ゲームの CPU は挙動がブラックボックスになりがちで、負けたときに「理不尽」「イカサマでは」という不信感を生む。
3. 心理戦・読み合いのあるボードゲームは、対面で人を集める必要がありプレイの敷居が高い。

---

## ターゲットユーザー

### ペルソナ

- 20〜40代のボードゲーム／パズル好き。運要素だけのゲームには物足りなさを感じている。
- 短時間（1プレイ 20 ターン以内）で、読み合いと最適化の手応えがある一人用対戦を求めている。
- 「敵の手が完全に読める状態で、いかに嵌めるか」を考えるのが好き。

## 主要機能の候補

### P0 (MVPで絶対必要)

1. **ビンゴカード**: 1〜25 をランダム配置した $5 \times 5$ 盤面（プレイヤー / CPU 各自）。
2. **コイン経済**: 初期 15 枚、上限 20 枚（超過分は消滅）、毎ターン開始時に全員へ 1 枚支給。
3. **ターンシークエンス（3フェイズ）**
   - フェイズ1「スキル宣言（同時解決）」: ターゲット番号 $T$ 公開後、同時宣言。
     - 【予知 Vision】3コイン: 山札の次の番号をのぞき見る
     - 【偏向 Shift】5コイン: $T$ を $+1$ / $-1$ ずらす
     - 【強奪 Greed】7コイン: 競り勝った場合の選択幅を $T \pm 2$（5択）に拡張
     - **バッティングルール**: 同一ターンに同じスキルが被ったら相殺。コストは没収され効果は発動しない。
   - フェイズ2「秘密オークション」: 秘密入札 → 公開。
     - 単独落札: 落札者のみ $\{T-1, T, T+1\}$ から自盤面の未マーク数字を 1 つ選択してマーク。
     - **敗者分配**: 勝者の支払いコインを敗者全員で均等分配（端数は中央銀行が回収）。
     - 同点1位が複数: 勝者なし（ズレ選択権なし）。同点者は全額支払い、盤面に $T$ があるときのみ自動マーク。支払い分は同点以外の敗者へ分配。
   - フェイズ3「クローズ＆ビンゴチェック」: 縦・横・斜めを判定。達成者がいれば終了。
4. **勝利条件判定**: 20 ターン以内に 1 ライン以上のビンゴを最速で達成した者の勝ち。
5. **非AI型オートマタ CPU 2体**（行動ルールを画面上に完全開示）
   - **レオ【クロックローダー】**: 4ターン周期の固定行動ループ（例: T1=入札1/スキル無、T2=入札3/予知、T3=入札5/強奪、T4=入札0/偏向）。予定ステップが開示されるため、あえてスキルをバッティングさせてコインを空費させられる。
   - **サラ【カウンターレプリカ】**: プレイヤーの「1つ前のターン」の入札額とスキルをそのまま模倣。時差を利用したコインハックが成立する。
6. **ゲーム UI**: 盤面・手持ちコイン・ターゲット番号・CPU 行動予定の開示・入札／スキル選択・ログ表示。

### P1 (重要だけど後回しでもいい)

- **提案A: ビンゴカードの整列化（空間的戦略）**: 1〜25 完全ランダムではなく「B列=1〜5、I列=6〜10」のように列ごとに範囲を制限し、$\{T-1, T, T+1\}$ の選択が「盤面で隣接するマスを連続で開ける」という視覚的・直感的な戦略に直結するようにする。
- リプレイ／対戦ログの振り返り表示。

### P2 (あったら嬉しい)

- **提案B: リアクションスキル（リアルタイム・インタラクション）**: 入札公開時にコインを払って割り込む要素。例:【関税】(勝者の支払いを +2 する妨害)、【保険】(敗北時に入札額の半分が戻る)。
- CPU キャラクターの追加（別パターンのオートマタ）。

## 技術的な検討事項

- Web アプリケーション（ブラウザで動作、単一プレイヤー vs CPU 2体）。
- テンプレート既定の Node.js v24 / TypeScript 6.x を想定。UI フレームワークは未定。
- サーバー不要のクライアント完結型で成立する見込み（対戦相手は決定論的オートマタのため）。オンライン対人戦は現時点でスコープ外。
- **ゲームロジックは UI から独立した純粋関数群として実装し、単体テストで検証可能にする**（バランス調整の検証が要になるため）。

---

## 非機能要件(とりあえず)

- 1 プレイ 20 ターンを数分で完了できる軽快な操作感。
- 乱数は再現可能（シード指定）にし、バランス検証・デバッグを可能にする。
- CPU の行動根拠が常に画面上で確認でき、「理不尽さ」を感じさせないこと。
- ルール上の全処理（分配の端数、コイン上限超過、バッティング相殺）が仕様どおりに決定的であること。

---

## 成功指標(とりあえず)

- **ユーザー視点**: 「運ではなく自分の判断で勝った／負けた」と感じられる。CPU の行動を読んで嵌める体験ができる。
- **プロダクト視点**: 支配的戦略（必勝法）が存在しない。特に「貯め込みスナイプ戦略」が敗者分配システムとコイン上限により無効化されていることを、シミュレーションで確認できる。

### 参考: バランス調整の経緯（Ver 1.0〜2.1 の課題と対策）

- **課題「貯め込みスナイプ戦略」**: 前半 0 入札でコインを貯め、CPU が貧困になった後半に高額入札を連発してマーク権を独占する戦略。原因は支払いコインが消滅（バーン）するデフレ経済。
- **対策1（Ver 2.2）敗者分配システム**: 勝者の支払いを敗者に等分配。高額入札は敵に軍資金を与えることになり連続独占が困難に。
- **対策2（Ver 2.2）財布の上限（20枚）**: 貯め込みは 20 枚でキャップされ超過分は消滅。前半から適度にコインを吐き出す必要が生まれる。

## まだ決めてないこと

- UI フレームワーク（React / Svelte / Vanilla TS 等）と状態管理の方針。
- 山札の構成（1〜25 をシャッフルして引き切るのか、毎ターン独立抽選か。20 ターンとの関係）。
- $T \pm 1$ / $T \pm 2$ が 1 未満・25 超になる場合の扱い（クランプするか、選択肢から除外するか）。
- 【予知】で見た次番号の情報を UI 上でどう保持・表示するか。
- 【偏向】が複数人で（相殺されずに）成立した場合の解決順序。
- 対戦人数の固定（プレイヤー1 + CPU2 の 3人固定か、可変か）。
- ビジュアルデザイン・キャラクター表現の方向性。
